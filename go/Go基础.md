## Go 和 Java 对比

- **优势**：Java 优势在生态，企业级应用；Go 优势在性能，天生高并发、轻量级
- **并发**：Java 用线程和锁；Go 用 Goroutine 和 channel

## GMP

- **G（ Goroutine）**：对协程优化，栈只有几KB，并发执行，充分利用多核CPU。特点：轻量
- **M（Machine）**：操作系统线程，绑定一个 P，执行 G
- **P（Processor）**：逻辑处理器，管理本地队列中的 G

### 工作原理

- 当一个 G 被创建时，它会被放入一个 P 的本地队列
- 当 P 的本地队列满了，或者某个 G 长时间没有被调度执行时，P 会尝试从全局队列中获取 G
- 如果全局队列也为空，P 会从其他 P 的本地队列中偷取一些 G，以保证尽可能多地利用所有的处理器
- M 的数量决定了同时并发执行的 G 数目。如果某个 M 阻塞（比如在系统调用中），它的工作会被其他 M 接管

### 设计策略（优点）

1. **复用线程**：避免频繁创建、销毁线程
   - work stealing 机制：本地无 G 时，尝试从其他 P 的队列中偷，而不是销毁线程
   - hand off 机制：G 阻塞时，M 和 P 解绑，P 和其他 M 绑定
2. **利用并行**
3. **抢占**：coroutine 需要主动释放，但在 goroutine 中最多 10ms G 会抢占 CPU，防止其他 G 被饿死
4. **全局 G 队列**

### GMP 里为什么要有 P？

1. **锁竞争**：M 执行和放回 G 都要访问全局 G 队列，互斥锁
2. **局部性差**：新创建 goroutine，不在一个 M 上执行
3. **系统调用**：线程阻塞，增加系统开销（无 hand off 机制）

## goroutine

1. **轻量**：轻量级线程，创建、销毁、上下文切换开销非常小
2. **并发**：并发执行，充分利用多核 CPU 性能。GMP 模型高效，运行时调度器
3. **简单**：使用 go 关键字就能创建一个 goroutine，通过 channel 通信和同步，避免多协程竞争问题

### panic 会导致整个进程崩溃吗？

goroutine 在同一个地址空间中运行，`panic` 时，如果不进行处理，默认情况下会导致整个进程崩溃。这是因为 `panic` 会传播到调用栈的顶层，如果没有被捕获和处理，最终会导致程序退出。

### goroutine vs 线程

| 特性 | 线程（Thread） | Goroutine |
|------|--------------|----------|
| 定义 | 操作系统管理的基本调度单位 | Go 语言中的轻量级线程 |
| 调度机制 | 抢占式调度，由操作系统内核负责 | 协作式调度，由 Go 运行时负责 |
| 资源消耗 | 创建和销毁开销大，上下文切换开销大 | 创建和销毁开销小，上下文切换开销小 |
| 并发和并行 | 可以在多核 CPU 上并行执行 | 通常在单个线程内并发执行 |
| 使用场景 | 计算密集型任务、多核 CPU 并行执行 | I/O 密集型任务、高并发处理、异步编程 |

### sync.WaitGroup

等待一组协程结束：`Add()`、`Done()`、`Wait()`

### 协程泄漏场景

1. channel 缺少接受者，导致发送阻塞，不能退出；缺少发送者，导致接收阻塞
2. 死锁
3. 无限循环

### 协程为什么支持高并发

1. **轻量级**：goroutine 是 go runtime 管理的轻量级线程，初始栈只有几kb，内存开销小、创建和销毁开销小
2. **非阻塞 IO + 事件驱动**：遇到 IO 阻塞时不会阻塞线程，而是让出 CPU 资源给其他协程。协程上下文切换远低于 OS 线程
3. **并发模型**：基于 CSP，通过 channel 实现 goroutine 之间的通信和同步
4. **调度器**：GMP workstealing 实现负载均衡

### 如何控制 goroutine 数量？

1. 有缓冲 channel + sync.WaitGroup
2. 无缓冲 channel + 任务发送/执行分离方式

## slice

slice 和 container/list 对比：

| 特性 | slice（切片/动态数组） | container/list（双向链表） |
|------|----------------------|--------------------------|
| 底层结构 | 连续内存块 | 离散节点（指针连接） |
| 访问效率 | O(1) 随机访问 | O(n) 随机访问（需从头遍历） |
| 增删效率 | 尾部 O(1)；头部/中间 O(n) | 任意位置 O(1)（前提是已拿到节点指针） |
| 缓存友好度 | 极高（利用 CPU 缓存行预取） | 极低（频繁触发 Cache Miss） |
| 类型安全 | 强类型（如 `[]int`） | 无（使用 `interface{}`，需频繁断言） |

- **数组**：长度固定，是值类型
- **slice**：是引用类型，动态数组，对数组的封装，包含数组 + len + cap

### slice 的坑

- 什么时候分离？--append 时触发扩容 > 1024 一次申请 1/4
- 作为入参，值传递，会进行拷贝
- 扩容策略：cap 不足以容纳新元素时，创建一个新数组，将现有元素拷贝到新数组中。通常是翻倍扩容，大切片会有调整为 1/4，防止一次性分配过多内存。高版本更平滑

### for range 遍历时变量地址是否会变？

取决于语言和版本，例如 Go 1.22 之后的版本变量地址会改变。

## string 和 []byte 区别

string 是不可变的字节序列，底层包含指向字节数组的指针和长度；`[]byte` 是可变的字节切片

1. **不可变性**：string 一旦创建就不能被修改，任何修改 string 的操作都会产生一个新的 string
2. **类型转换**：`[]byte(s)` 将 string 转换为 `[]byte`，`string(b)` 将 `[]byte` 转换为 string
3. **内存分配**：string 内存由 Go 运行时管理；`[]byte` 内存由程序员负责
4. **Unicode 字符**：string 中每个元素是一个 Unicode 字符，`[]byte` 中每个元素是一个字节

## context 实现

提供了一种在多个 Goroutine 之间传递请求范围内的数据、取消信号和截止日期的方法

### 用途

1. **取消信号**：在多个 Goroutine 之间传递取消信号
2. **超时控制**：设置操作的截止日期或超时时间
3. **传递元数据**：在请求范围内传递一些元数据，如用户身份、请求 ID 等

### 接口定义

```go
type Context interface {
    Deadline() (time.Time, bool)
    Done() <-chan struct{} // ctx 被关闭或取消时能收到取消信号
    Err() error            // 能获取到取消的原因
    Value(key interface{}) interface{}
}
```

## map

map 实现了 hash 表：count、B、buckets、oldbuckets

### 扩容策略

- **翻倍扩容**：负载因子 = 键值对个数/桶个数
- **等量扩容**：noverflow 较多（很多键值对被删除）

### key 的条件

必须是可比较的，即必须是可以被 hash 的。否则无法处理 hash 冲突。

### sync.Map

- 实现原理：read、dirty、mutex、miss
- 读写分离(COW)，降低锁粒度，适合读多写少，read 类似缓存，读不加锁
- read 中没有则记录 miss++，去 dirty 中找，miss 达到一定数量触发 dirty 覆盖 read

### hash 算法

任意长度转换为固定长度，常用 MD5/SHA1/SHA256

## Channel

- **无缓冲 channel**：发送的数据如果没有被接收方接收，发送方阻塞；一直接收不到发送方的数据，接收方阻塞。用于严格同步和协调
- **有缓冲 channel**：发送方在缓冲区满时阻塞，接收方不阻塞；接收方在缓冲区为空时阻塞，发送方不阻塞。用于提高传输效率和吞吐量
- **特性**：空读写阻塞，写关闭异常，读关闭空零

### 关闭 channel 引发 panic

未初始化时关闭、重复关闭、写关闭

### 如何安全读取关闭后的通道

1. `x, ok := <-ch` 当获取到 ok==false 后，将 ch 置为 nil
2. `for x := range ch {}`

### 无缓冲 channel 容易死锁的情况

1. channel 要用 make 进行初始化操作
2. 读取和写入要配对出现，并且不能在同一个 goroutine 里
3. 一定先用 go 起一个协程执行读取或写入操作
4. 多次写入数据，for 读取数据时，写入者注意关闭 channel

### 有缓冲 channel 总结

1. 如果 channel 满了，发送者会阻塞
2. 如果 channel 空了，接收者会阻塞
3. 如果在同一个 goroutine 里，写数据操作一定在读数据操作前

## select

```go
select {
case <-ch:
case val <-ch2:
    fmt.Println("Received:", val)
default:
}
```

- select 在所有 case 都阻塞时进入 default
- 没有 default 时一直阻塞

### for 循环 select 时通道关闭的情况

- 如果其中一个 case 通道已经关闭，则每次都会执行到这个 case
- 如果 select 里只有一个 case，而这个 case 被关闭了，则会出现死循环

## 内存管理

### 内存分配

1. **栈内存**：存储局部变量和函数调用栈，分配速度快，但空间有限
2. **堆内存**：new/make 分配，空间大，但分配和回收慢

### 内存分配器

tcmalloc 根据对象大小将内存分为不同的大小类，以提高分配和回收的效率

### 逃逸分析

- 编译器在编译时进行逃逸分析，确定变量分配在栈上还是堆上
- 函数返回后仍存在，则分配在堆上，否则分配在栈上
- **主要关注点**：变量的生命周期和作用域，而不是变量的大小

#### Q&A

- **Q：局部变量分配在栈上还是堆上？**
- **A**：编译器决定，判断变量作用域没有超出函数范围则在栈上，否则分配在堆上

- **Q：函数返回局部变量的指针是否安全？**
- **A**：安全

## 虚拟内存

虚拟内存的目的是为了解决以下几件事：

1. 物理内存无法被最大化利用
2. 程序逻辑内存空间使用独立
3. 内存不够，继续虚拟磁盘空间

## GC

### 版本演进

- **Go V1.3**：普通标记清除法，整体过程需要启动 STW，效率极低
- **Go V1.5**：三色标记法，堆空间启动写屏障，栈空间不启动，全部扫描之后，需要重新扫描一次栈（需要 STW），效率普通
- **Go V1.8**：三色标记法，混合写屏障机制，栈空间不启动，堆空间启动。整个过程几乎不需要 STW，效率较高

### 标记清扫（1.3 之前）

- 缺点：STW 暂定整个程序，扫描整个 heap，产生碎片
- 流程：暂停 → 标记 → 恢复 → 清除

### 三色标记（1.5）如果没有 STW

在扫描过程中，任意对象均可能发生读写，GC 可能误杀

- 白被黑引用
- 灰取消白引用

引入屏障机制防止白对象误杀

- 插入写屏障：STW 重新扫描栈
- 删除写屏障：回收精度低

## new 和 make 区别

- **内存分配方面**：基本类型只用声明，自动分配内存；但非基本类型不光要声明还要通过 new/make 分配内存
- **指针(引用类型)**：声明后初始为 nil，还要分配内存：new、make
- **相同**：一般都在堆上分配（不考虑逃逸）
- **不同**：make 只能用在 slice、map、channel；new 会初始化为 0，但不常用，通常 `i:=0`、`u := User{}`

### Go 的引用类型

Go 没有显式引用类型，引用通常指的是通过指针间接访问变量。

Go 语言中的一些内置类型本质上是引用类型，包括切片（slice）、映射（map）和通道（channel）。这些类型在传递时是按引用传递的，即传递的是指向底层数据结构的指针。

## interface

1. 是方法声明的集合
2. 任何 struct 实现了在 interface 中声明的全部方法，则表明该 struct 实现了该接口
3. interface 可以作为一种数据类型，实现多态

### 和 Java 区别

不需要通过 implements 显式说明实现了某个 interface，隐式实现 interface 的所有方法即可

### 好处

灵活，易拓展。开闭原则：在修改需求的时候，应该尽量通过扩展来实现变化，而不是通过修改已有代码来实现变化

### 意义

多态，设计 API 接口，抽象设计框架，适用于现在也适用于未来

### 两个 interface 能比较吗？

interface 内部包含两个字段：类型 T 和值 V。可以使用 == 和 != 比较。相等的情况：

1. 两个 interface 均等于 nil
2. 类型 T 相同，对应的 V 值相等

## init() 什么时候执行

执行顺序：`import` → `const` → `var` → `init()` → `main()`

- 每个包首先初始化包作用域的常量和变量（常量优先于变量），然后执行包的 init() 函数
- 同一个包，甚至是同一个源文件可以有多个 init() 函数
- init() 函数没有入参和返回值，不能被其他函数调用
- 同一个包内多个 init() 函数的执行顺序不作保证
# Go协程和Python协程区别

Go协程（goroutines）和Python协程有一些本质区别，主要体现在它们的设计哲学、实现机制以及使用方式上。下面是一些关键的不同点：

1. **设计哲学和模型**:
   * **Go协程**: Go的并发模型基于"CSP"（Communicating Sequential Processes）理论，强调通过通道（channels）进行通信，而不是通过共享内存。Go协程是由Go运行时（runtime）调度的，运行时负责在可用的物理线程上调度执行协程。这种模型使得Go协程非常轻量，创建成本低，可以轻松创建成千上万个协程。
   * **Python协程**: Python的协程是基于"异步IO"（asyncio）的概念，用于IO密集型任务，特别是在网络编程中。Python协程依赖于事件循环（event loop），通过`async`和`await`关键字使得异步代码的编写和理解更接近于同步代码。Python的协程是协作式的，意味着一个协程需要显式"让出"控制权（通过`await`），其他协程才能运行。
2. **调度和执行**:
   * **Go协程**: Go协程的调度是由Go语言的运行时负责的，不需要开发者介入。Go运行时包含了自己的调度器，可以在用户级别进行多任务的调度，而不依赖于操作系统的线程调度。这意味着Go协程的上下文切换非常快。
   * **Python协程**: Python协程的执行依赖于事件循环，通常是单线程的，尽管可以使用库如`asyncio`来管理协程的调度。Python 3.5及之后版本通过引入`async`和`await`语法，简化了异步编程的复杂性。Python的异步IO模型依赖于协程主动让出控制权（通过`await`），这种方式更多地依赖于开发者对协程的显式管理。
3. **使用场景**:
   * **Go协程**: 适用于并发和并行任务，特别是CPU和IO密集型任务。Go的并发模型使其在网络服务和微服务架构中表现出色。
   * **Python协程**: 主要用于IO密集型任务，尤其是在需要大量网络请求和IO操作时。Python的异步IO模型并不适合CPU密集型任务，因为Python全局解释器锁（GIL）的存在限制了代码的并行执行。
4. **性能和资源消耗**:
   * **Go协程**: Go协程非常轻量，每个协程的堆栈内存起始大小仅需几KB。这意味着在相同的硬件条件下，Go可以同时运行更多的协程。
   * **Python协程**: Python协程的资源消耗相对较小，但是由于GIL的存在，它们在多核处理器上的并行能力受限。不过，对于IO密集型任务，Python协程可以显著提高性能和资源利用率。

总的来说，Go协程和Python协程各有特点，它们适用于不同的场景和需求。Go协程更适合需要高并发处理的场景，而Python协程则更适用于IO密集型任务，尤其是当涉及到异步处理时。
